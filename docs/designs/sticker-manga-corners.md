## Problem Statement

The app's manga look is shōnen action-panel only: 3px black ink borders, hard offset
shadows, and square corners everywhere. The owner uses it daily and wants it to feel
softer and smoother while staying clearly manga.

Square corners are hand-written all over the codebase, not set in one place:
- 61 explicit `rounded-none` overrides in 33 files, mostly fighting shadcn primitives that
  default to `rounded-lg` / `rounded-xl`.
- 55 files [measured: grep, 2026-10-23] draw thick-bordered blocks (`border-2/3/4`) with no radius class at all.
- The `--radius` token (0.5rem) in `src/app/globals.css` is read only by untouched shadcn
  defaults, so changing it alone softens almost nothing.

## What Makes This Cool

Manga already has a soft dialect: round speech bubbles, puffy thought clouds, chibi frames,
die-cut stickers on a tankōbon cover. The restyle switches dialect instead of diluting the
style. Every card becomes a vinyl sticker: rounded die-cut corners, the same thick ink, the
same hard offset shadow (a `box-shadow` follows `border-radius`, so the "ledge" survives
untouched). Presses ease with a small spring instead of snapping, like pressing a sticker
flat.

## Constraints

- Visual only. No layout, colour, copy, or behaviour changes. No new dependencies.
- Both themes (day and light-up) must keep working; light-up retints shadows via
  `--manga-offset` / `--manga-line` and must not need per-theme radius work.
- Follow `.agents/rules/frontend-ui.md`: tokens before one-offs, primitives in
  `src/components/ui`, `cn(...)` for class merging.
- Tailwind v4: `rounded-none` is a hard-coded `border-radius: 0`, not a token, so every
  occurrence must be edited; it can't be re-pointed from the theme.

## Premises (agreed)

1. The manga identity is ink borders + hard offset shadows + the black/red/paper palette.
   Square corners are not part of it.
2. Softness comes from tokens in `globals.css`, not hand-typed numbers. Softness is tuned
   later by changing one value, and light-up inherits it.
3. Radius scales with size, and nested blocks use a smaller radius than their parent so
   inner corners don't pinch.
4. Already-round things stay round (switches, sliders, `rounded-full` circles, speech bubbles
   at `rounded-[1.6rem]`). The jagged shout bubble (`clip-path` polygon) stays jagged.
5. "Smooth" = the press eases (~180ms, slight spring) instead of snapping, off under
   `prefers-reduced-motion`.
6. Visual only (see Constraints).

## Decisions

- **Feel: sticker / chibi.** Rounded corners, thick ink and hard shadows kept. Chosen over
  gentle shoujo (thinner borders, blurred shadows), subtle trim, and mixed-by-role.
- **Comic layer: rounded too.** `ComicPanel` gets the panel radius like every other block.
  Chosen over keeping comic frames square as "printed manga".
- **Motion: corners + gentle press.** Chosen over corners-only and full sticker motion
  (hover lift).
- **Radii: approved from the live sketch at the defaults.**

  | Role token        | Value | Utility           | Used by |
  |-------------------|-------|-------------------|---------|
  | `--radius-shell`  | 20px  | `rounded-shell`   | `MangaPageShell` |
  | `--radius-panel`  | 14px  | `rounded-panel`   | `MangaPanel`, `ModuleCard`, `ComicPanel`, `MetricTile`, dialogs, dropdown/select popups, any card-sized block (edge-attached sheets stay square, R5) |
  | `--radius-control`| 10px  | `rounded-control` | `MangaButton`, `IconButton`, inputs, textarea, select trigger, tabs, `QueueRow`, row-sized blocks |
  | `--radius-tag`    | 6px   | `rounded-tag`     | `PageTag`, badges, chips, checkbox, tooltip, stamps |

## Approaches Considered

- **A: CSS safety net** (one unlayered rule matching `[class*="border-3"]` inside
  `.manga-shell`). Rejected: guesses by class substring, rounds unintended strips, misses
  portaled dialogs/menus outside `.manga-shell`, leaves 61 `rounded-none` lines lying.
- **C: `stickerSurface()` cva helper** bundling border + radius + shadow + press, migrating
  ~150 shadow strings. Rejected for now: a refactor, not a restyle (premise 6). Good
  follow-up if shadow depth or border weight ever needs a one-line change too.

## Recommended Approach: B — role tokens + primitives + sweep

### 1. Tokens (`src/app/globals.css`)
Declare the knobs once in `:root` (theme-independent, so light-up inherits them), so
hand-written CSS can read them as runtime variables:

```css
:root {
  --sticker-shell: 20px;
  --sticker-panel: 14px;
  --sticker-control: 10px;
  --sticker-tag: 6px;
  --sticker-ease: cubic-bezier(0.34, 1.56, 0.64, 1); /* press: small squish overshoot */
  --sticker-ease-out: cubic-bezier(0.22, 1, 0.36, 1); /* release: no overshoot */
}
/* Design review 6.1: on phones the shell sits 12px from an already-curved screen
   edge, so its corner drops to the panel size. Only the shell changes; the dashed
   inner frame follows through the same calc (stays concentric). */
@media (max-width: 639px) {
  :root {
    --sticker-shell: 14px;
  }
}
```

Then map them into the `@theme inline` block next to the existing `--radius-sm..xl`, the
same way that block already maps `--color-manga-*` to `var(--manga-*)`:

```css
--radius-shell: var(--sticker-shell);
--radius-panel: var(--sticker-panel);
--radius-control: var(--sticker-control);
--radius-tag: var(--sticker-tag);
```

Tailwind v4 turns each into a `rounded-<role>` utility (plus `rounded-t-<role>` etc.), and
because the value is `var(--sticker-*)`, CSS rules in `globals.css` use the same knob.
Leave `--radius` and `--radius-sm..xl` alone; untouched shadcn internals still read them.

### 1b. Teach `cn` the new radius names (`src/lib/utils.ts`)
`cn` is plain `twMerge`, whose default radius scale only knows t-shirt sizes. Without this
step `cn('rounded-lg', 'rounded-control')` keeps BOTH classes and stylesheet order, not
className order, picks the winner (that's why `rounded-none` worked before and role names
wouldn't). Switch to `extendTailwindMerge`:

```ts
const twMerge = extendTailwindMerge({
  extend: { theme: { radius: ['shell', 'panel', 'control', 'tag'] } },
})
```

Extend the existing `src/lib/utils.test.ts` (it has one px-merge row at line 7; eng review
correction) with rows asserting `cn('rounded-lg', 'rounded-control') === 'rounded-control'`,
`cn('rounded-panel', 'rounded-control') === 'rounded-control'`,
`cn('rounded-none', 'rounded-panel') === 'rounded-panel'`, and that a variant-scoped
`data-[side=right]:rounded-l-panel` survives next to `rounded-panel`. This is what makes the
nested-block rule (a child passing `className="rounded-control"` into `MangaPanel`) work.

### 3. Sweep (feature components and pages)
Work from two lists, classifying every hit as **block**, **divider**, or **media**:
- 33 files with `rounded-none` (largest: `PageSkeletons.tsx` 8, `DictationSegmentEditor.tsx` 5,
  `DictationCaptionManager.tsx` 5, `DictationPracticeShell.tsx` 4, `QuickVocabLookup.tsx` 3).
- 55 files [measured] with `border-2/3/4` and no `rounded` class (home, dictation browse/admin,
  grammar modals/report/map, vocabulary dashboard, admin pages, loading skeletons).

Plus a third list the grep can't see: **CSS-authored blocks in `globals.css`**. Known one:
`:root[data-theme='lightup'] .page-hero` (globals.css ~line 326) draws `border: 3px solid`
plus an offset shadow in light-up only, so route heroes would stay square in light-up.
Give it `border-radius: var(--sticker-panel);`. Audit every other `border:` /
`box-shadow:` rule in `globals.css` the same way (the scrollbar thumb is already round).

Rules:
- **Block** (a box with a full border): add the role utility by size.
- **Divider** (`border-t-3`, `border-b-3`, dashed separators): no radius.
- **Media** (YouTube player, video thumbnails, sensei portrait): round the wrapper and add
  `overflow-hidden` so the iframe/image is clipped; never round an `<iframe>` directly.
- **Full-bleed strips** (`-mx-4 -mt-4` headers such as `HomeStudyDesk.tsx:230`): no radius of
  their own; confirm the parent has `overflow-hidden` (that one does) so the parent's corner
  clips them.
- **Nested blocks:** child radius ≤ parent radius. A card inside a card uses `rounded-control`.
  A flush child (touching the parent's border) gets the parent radius minus the parent's
  border width, or no radius and the parent's `overflow-hidden` clips it (eng review R6/D7).
- **Skeletons match their target** (design review 2.1): every skeleton in
  `src/components/common/PageSkeletons.tsx` (30, all `rounded-none` today) and the 3
  `loading.tsx` routes uses the same role as the real block it stands in for (card skeleton
  `rounded-panel`, button/input skeleton `rounded-control`, text-line and tag skeleton
  `rounded-tag`, video thumbnail skeleton = its media wrapper's radius). Loading to content
  must not snap shape.
- Leave `rounded-full`, `rounded-[1.6rem]` speech bubbles, and the shout `clip-path` alone.
- **Borderless overrides** (eng review R7/D8): a `rounded-none` on a borderless element gets the
  role by size (tab list `rounded-control`, tab triggers / menu items / tooltips `rounded-tag`),
  never a bare deletion that falls back to shadcn's `rounded-md`/`rounded-lg`. CardHeader /
  CardFooter `rounded-none` overrides are simply deleted.

### 4. Gentle press
On the press-animated controls (11 `active:translate-x-*` sites: `MangaButton`,
`IconButton`, `ModuleCard`, `MetricTile`, `VocabularyWordList` x2,
`VocabularyExplorePanel` x2, `VocabTermHeader`, `VocabRecallModal`, `AdminVocabPanel`):
`duration-*` / `ease-*` utilities apply one timing to every property, so per-property
timing needs one shared class. Add to `globals.css` **unlayered** (not inside any
`@layer`), like the existing light-up shadow rules: unlayered CSS beats Tailwind's
`@layer utilities`, which is what lets it override the `transition-all` that `MangaButton`
inherits from `buttonVariants` (tailwind-merge doesn't know `sticker-press` is a transition
class, so it won't strip it):

```css
/* Tailwind v4 `translate-*` sets the standalone `translate` property, not
   `transform`, so `translate` must be listed or the press still snaps.
   Release (base state) eases out with no overshoot; press (:active) gets the
   spring, because the transition on the state being ENTERED is the one that
   runs (design review 3.1: squish down, smooth up). */
.sticker-press {
  transition:
    translate 180ms var(--sticker-ease-out),
    transform 180ms var(--sticker-ease-out),
    box-shadow 180ms var(--sticker-ease-out),
    background-color 150ms linear,
    color 150ms linear;
}
.sticker-press:active {
  transition:
    translate 180ms var(--sticker-ease),
    transform 180ms var(--sticker-ease),
    box-shadow 180ms var(--sticker-ease),
    background-color 150ms linear,
    color 150ms linear;
}
@media (prefers-reduced-motion: reduce) {
  .sticker-press,
  .sticker-press:active {
    transition: background-color 150ms linear, color 150ms linear;
  }
}
```

At each of the 11 sites, replace the existing `transition-[...] duration-150` (or
`transition-transform`) with `sticker-press`; the `active:translate-*` / `active:shadow-none`
classes stay as they are. Under reduced motion the press still moves (instantly) and only
the spring is removed.
MetricTile's press goes to `active:translate-x-1 active:translate-y-1` (4px) to match its 4px
shadow, as ModuleCard already does (eng review R8/D9).

**Press vector fix (eng review R1/D2).** `button.tsx:7`'s base
`active:not-aria-[haspopup]:translate-y-px` out-specifies `active:translate-y-[3px]`
(`:active:not([aria-haspopup])` beats `:active`), so MangaButton and IconButton currently
press (3px, 1px) and miss their shadow. Add `active:not-aria-[haspopup]:translate-y-[3px]`
to both components' class lists; `cn` then drops the base 1px rule (same modifiers).
Leave the base rule in `button.tsx` so plain Buttons keep shadcn's 1px nudge.

**Light-up press (eng review R3/D4).** The light-up shadow retints in `globals.css`
(line 454 onward) are unlayered and beat `active:shadow-none`, so in light-up the ledge never
drops on press. Add, unlayered, next to `.sticker-press`:

```css
:root[data-theme='lightup'] .sticker-press:active {
  box-shadow: none;
}
```

Place it AFTER the light-up retint block: both selectors are (0,3,0) and unlayered, so
source order decides. Also (eng review R4/D5): the three manga-styled raw `<Button>` sites
get the same override, `active:not-aria-[haspopup]:translate-y-[3px]` on
VocabularyExplorePanel.tsx's prev/next buttons and `-[2px]` on VocabTermHeader.tsx's speak
button, matching their shadows.

## Design Review: Containment Hierarchy (Pass 1 record)

Radius encodes nesting depth: a bigger radius means an outer container. Layout and content
order are unchanged by this plan.

```
MangaPageShell ............ rounded-shell 20px (14px < 640px)
 ├─ AppTopbar / footer .... full-bleed strips, clipped by the shell corner
 └─ <main> (pages pad ≥16px)
```
