## Problem Statement

English For Only Me is noticeably slower than the owner's other four Vercel Pro
projects (AnphaShop, Deewas, MonaEdu, Port4lio). The owner feels two kinds of
slowness: **clicks feel laggy** (each answer, mark or toggle waits on a server
round trip) and **first load is slow** (cold page opens take seconds). They
use every surface: dictation practice, vocabulary recall, grammar, and
browsing/home.

Three read-only audits (server rendering, client bundle, mutation map) found
no single bug. The costs come from several problems stacked on top of each
other:

1. **Region mismatch (multiplier).** The Atlas cluster `maincluster.solhqvo`
   resolves to Hong Kong (159.143.161.29, AS8011). No `vercel.json` or
   `preferredRegion` exists, so functions likely run in the default iad1
   (Washington DC). That is roughly 200 ms per database round trip, and every
   sequential query below pays it.
2. **Cold-start DB cost.** `src/lib/db/connectDatabase.ts:27` uses mongoose
   defaults: `autoIndex` and `autoCreate` are on, so roughly 80 `createIndex`
   calls run across 18 models on every cold start, and
   `serverSelectionTimeoutMS` is 30 s.
3. **Unbounded per-view loads.** `globalStatsService.ts:17-36` loads every
   attempt and review item the user owns, plus every video in the catalog
   (archived ones too), with no projection. The 4 queries already run in
   parallel, but the `createdAt` sort on attempts has no
   `{userId, createdAt}` index. It runs on `/` and `/dictation`, and
   `/dictation` also runs `getCompletionCountsForUser` a second time.
   `vocabWordListService.ts:165-181` is unbounded. `listGrammarPoints` loads
   200 full documents for a map.
4. **Waterfalls.** The practice page runs 4 sequential round trips, the topic
   page 4, and the grammar lesson page 5-6.
5. **Nothing is cached.** 21 pages are `force-dynamic`. There is no
   `unstable_cache` or `use cache`, so shared catalog data (topics, sections,
   videos, grammar taxonomy and lessons) is re-queried on every request.
6. **Blocking clicks.** Vocab recall, grammar recall, vocab marks, word list
   status changes, grammar point actions and quick lookup all await the
   server. After a small mutation the vocab dashboard refetches 3 endpoints,
   including about 10 stats queries and up to 1000 recall tasks.
7. **Client weight.** About 70 KB gzipped of Base UI popup code ships on every
   page (UserMenu in the top bar), plus about 114 KB more on practice. The
   practice page loses its server HTML because preferences come from
   localStorage in the `useState` initializer, so the client render
   mismatches. Every keystroke re-renders the whole practice shell. The
   YouTube player and thumbnails load eagerly and at full size.

## What Makes This Cool

Every click in a study session should feel instant: answer, see the verdict,
move on, with the server catching up behind you. A failure should never lose
an attempt, and it should never quietly show a state the server rejected.
The app should feel as fast as the owner's other sites, or faster, because
grading runs locally.

## Constraints

- Next.js 16.2.10 App Router, React 19.2, mongoose 9, next-auth 5 beta (JWT
  sessions, so `auth()` never hits Mongo). Read `node_modules/next/dist/docs/`
  before using any caching API.
- Vercel Pro team shared by 5 projects. The function region is a project
  setting. `vercel.json` `regions` works on Pro.
- Multiple real users exist (see the user-data isolation memory): guest ids
  are an httpOnly cookie, and signed-in ids come from the JWT. Any client
  cache or outbox must be keyed by owner.
- Repo conventions: client-minted `idempotencyKey` plus a unique index on
  `(userId, idempotencyKey)` with an early-return lookup (see
  `VocabRecallAttemptModel.ts`, `recallAnswerService.ts`,
  `DictationAttemptModel.ts`). Reuse this, do not invent a new one.
- The `MONGODB_URI` in `.env` points at Production. No migration or index
  build runs from this checkout without the owner explicitly asking.
- No em dashes in any written text in this repo.

## Premises (agreed)

1. **Region first.** Pin the Vercel functions to `hkg1` to match Atlas. It is
   the cheapest big win, and every other server fix multiplies with it.
2. **Cache shared catalog data** with tags and invalidate it from admin
   actions, instead of querying it on every request.
3. **Make clicks client-first** through a shared owner-keyed outbox with
   ordered lanes, merged writes, idempotency keys, rollback and a beacon on
   tab close. Start with vocab recall, dictation attempts, grammar recall and
   status marks. The owner accepts sending grammar recall `acceptedAnswers` to
   the client so it can grade locally. The grammar **test** keeps hiding its
   answers.
4. **Fix two correctness bugs first,** because the client-first work builds
   on them:
   - Per-user dictation progress is written onto the shared `DictationSegment`
     (`attempts/route.ts:195-200`, read at `DictationPracticeShell.tsx:243,747`
     and `DictationFullTranscript.tsx:150`).
   - `patchSession` cursor moves (`DictationPracticeShell.tsx:400-414,
461-479`) run outside `persistQueueRef`, so they race queued attempts
     and cause 409s that silently drop those attempts.

## Approaches Considered

### Approach A: Server tune-up

Region pin, DB options, stats rewrite, `Promise.all` waterfalls,
`unstable_cache` for the catalog, lazy popups, image fixes, the hydration fix
and the two bugs. Effort M, risk low. Clicks still wait on a (faster) round
trip.

### Approach B: Client-first plus tagged caching (CHOSEN)

A, plus the outbox, browser grading with parity tests (the server re-grades
and wins), vocab data loaded on the server, React Compiler, `staleTimes`, and
moving side work into `after()`. Effort L, risk medium.

### Approach C: B plus a Cache Components migration

Turn on `cacheComponents`, remove 21 `force-dynamic` configs, and restructure
every page into a static shell with Suspense streaming. Effort XL, risk high.
Deferred: `loading.tsx` already gives instant skeletons, and C is best judged
after B has been measured.

## Recommended Approach: B, in five workstreams

### WS0 - Measure (before anything else)

Record **read-only** baselines; this checkout's DB is Production, so
benchmarks never write.

- **Local:** `next build && next start`, then GET `/`, `/dictation`, a topic,
  a practice page, `/vocabulary` and `/grammar` as a guest. Record TTFB, the
  server-side query count and duration (via a temporary mongoose debug
  counter that is never committed), and client JS gzipped per route from the
  build manifests.
- **Live:** GET the same anonymous and guest pages on the deployed site
  before and after the region pin, so the region change shows up in the
  numbers (local runs cannot see it).
- Click-to-verdict is measured as code-path latency in unit-level timing:
  local grading versus awaiting a POST. No writes against Production.

### WS1 - Correctness first

- **Per-user segment progress.** Stop writing user progress onto
  `DictationSegment`. Derive each per-segment field the shell reads (exact
  field list fixed in eng review from `attempts/route.ts:195-200`) from that
  user's attempts in the current session: latest attempt per segment, its
  verdict, and whether it was revealed or skipped. Compute it in the practice
  page loader and return it in the attempt response. Keep the shared segment
  fields content-only. Read paths stop using the polluted fields. A cleanup
  script is optional and is **not** run against Production automatically.
- **Ordered dictation lane.** Attempts, cursor moves and completion go
  through one ordered queue. Consecutive cursor moves merge. On 409 the
  attempt is re-sent with the server cursor, never dropped.

### WS2 - Server path

- `vercel.json` `{"regions": ["hkg1"]}` (confirm in the Vercel dashboard that
  no project override conflicts).
- `connectDatabase`: `serverSelectionTimeoutMS: 5000`, `maxPoolSize: 10`,
  `maxIdleTimeMS: 60000`, and `autoIndex`/`autoCreate` off **in production
  only** (dev keeps building indexes). `@vercel/functions` is not a
  dependency, so `attachDatabasePool` is skipped. Index creation in
  production moves to `scripts/syncIndexes.ts` (`bun run db:sync-indexes`).
  **Ordering rule:** this plan adds no new unique index that code depends
  on. Any new non-unique index (such as `{userId, createdAt}` on
  `DictationAttempt`) only speeds things up, so shipping before the owner
  runs the script is safe.
- Global stats: bounded, projected queries (not one cross-collection
  `$facet`). Replace the video load with `countDocuments` and a `distinct`
  over completed video ids, and drop the duplicate completion count. Add a
  parity test that the new output equals `aggregateGlobalDictationStats`
  for a fixture. Declare `{userId: 1, createdAt: 1}` on `DictationAttempt`.
- Waterfalls to `Promise.all` on the practice, topic and grammar lesson
  pages. Run `auth()` and `connectDatabase()` together. Wrap
  `getOptionalUser` in React `cache()`.
- Projections: `listGrammarPoints` `.select()`, transcripts
  `.select('language rawCues')`, and vocab word list pagination (50 per page
  plus a cursor) with projection.
- Catalog caching: `unstable_cache` with tags `dictation-catalog` and
  `grammar-content` for topic summaries, a topic by slug, sections, videos
  for a topic, the no-topic count, grammar lessons, the taxonomy list and
  sitemap data. Cached functions call `connectDatabase()` themselves, read no
  cookies, and return plain JSON-safe records (ids as strings, dates as ISO
  strings parsed back by the caller), because `unstable_cache` serializes
  them. Admin server actions call `updateTag(tag)` (read-your-writes); route
  handlers call `revalidateTag(tag, 'max')`. The cache survives deploys, so
  seed scripts and the content backfill end by calling a secret-protected
  `POST /api/admin/revalidate` (or the owner presses an admin "refresh
  content" action). Verify every API against `node_modules/next/dist/docs/`
  before writing it.
- `after()` only for side work that is safe to lose and retry later:
  occurrence recording in vocab lookup. The dictation review-item recompute
  stays awaited but becomes incremental (only the attempted segment's review
  item, not every attempt for the video), so it stays correct on replays.
- Remove the client `router.refresh()` calls that follow server actions which
  already `revalidatePath` (admin reorder, move, assign, level).

### WS3 - Client-first interactions

- **`src/lib/sync/outbox.ts`:** an owner-keyed outbox with ordered lanes,
  merge-by-key, an idempotency key minted once when a write is queued, and
  persistence in localStorage. Every write is tagged with its owner.
  - **Flushing:** `fetch(..., {keepalive: true})` on pagehide (64 KB cap, so
    it flushes in small batches). Items stay queued until a response
    confirms them; anything still queued at startup is replayed, which is
    safe because every write is idempotent.
  - **Multiple tabs:** only the tab holding a Web Lock (`navigator.locks`)
    flushes. Other tabs enqueue and hear about updates over a
    BroadcastChannel.
  - **Owner change:** when the owner changes (guest signs in), the previous
    owner's queue is flushed under that owner's cookie before the switch, or
    dropped with a visible notice if it can't be.
  - **Failures:** retry with backoff on network errors and 5xx. On 4xx,
    roll back and show a visible error. `whenIdle()` waits for every write to
    land.
  - Generalize the existing Explore queue in
    `VocabularyDashboard.tsx:184-345` rather than building something parallel
    to it.
- **`useOptimisticMutation`:** apply the change, snapshot the old state,
  reconcile with the server response or roll back.
- **Owner key:** the server passes `ownerKey` (the user id, or the existing
  guest id read from the cookie, or `null`) as a prop. When it is `null`, the
  client calls a new `POST /api/guest` once before the first write; that
  call mints the cookie and returns the id. That removes the parallel
  first-request mint race without extending the proxy matcher. Draft and
  preference storage keys get namespaced by owner too.
- **Vocab recall:** grade in the browser from the task token payload. Predict
  the next stage with `applyRecallAnswer`. Queue the POST with a per-task
  idempotency key. Refresh stats once per session, not per card. A queued
  answer whose token has expired (30 min) is shown as "not saved" on that
  card in the session summary, never dropped silently.
- **Dictation:** score immediately, even before the session POST resolves.
  Attempts queue in the dictation lane behind session creation, so no new
  route shape or unique index is needed. Results waits for `whenIdle()`.
- **Grammar recall:** send `acceptedAnswers` with each task and run
  `resolveGrammarAnswer` in the browser. The server re-grades and wins, and a
  disagreement updates the UI. Prefetch the due queue.
- **Marks and status:** vocab mark, word list status, grammar
  Start/Known/Skip and quick-lookup mark go through the outbox. Favorites use
  an idempotent `setFavorite(desired)`.
- **Parity tests** for `recallLadder` and `resolveGrammarAnswer`, alongside
  the existing dictation `correctionParity.test.ts`.

### WS4 - Client weight

- Lazy-load `UserMenu`'s dialog and menu, the practice popups and Select, and
  the recall and test modals with `next/dynamic`. Replace the logo Tooltip
  with `title`.
- Practice hydration: read preferences via `useSyncExternalStore` with a
  server snapshot equal to the defaults. This accepts a one-frame flash of
  the defaults before saved preferences apply, in exchange for keeping the
  server HTML. A preferences cookie read on the server would remove the
  flash; that is decided in eng review.
- React Compiler (`reactCompiler: true` plus `babel-plugin-react-compiler`).
  Debounce the draft write to localStorage. Read `currentAnswer` through a
  ref in `runAttempt`.
- YouTube: preconnect, and create the player on idle or Start.
- Thumbnails: `mqdefault`, `fetchPriority` on the first row, and Cloudinary
  `f_auto,q_auto,w_160` for topic tiles.
- Vocabulary: fetch initial stats, due and explore data in the server page
  and pass them as props.
- Practice payload: send only the selected language's translations.
- `staleTimes` is **not** used: outbox writes go to route handlers, which do
  not clear the client router cache, so back-navigation would show stale
  progress.
- React Compiler and the CSS items below land as their own commits at the
  end, so they are easy to revert if they cause a regression.
- CSS: replace `background-attachment: fixed` with a fixed pseudo layer, and
  stop the lamp's infinite animation.

## Success Criteria

- Click-to-verdict on vocab recall, grammar recall and dictation Check is
  under 50 ms (local grading), independent of network.
- Warm TTFB on `/`, `/dictation` and the practice page drops at least 50%
  from the WS0 baseline. The cold-start first byte drops measurably once
  `autoIndex` is off.
- `/` client JS drops by at least 60 KB gzipped.
- No attempt is lost when the tab closes mid-queue or a cursor move races an
  attempt (covered by tests).
- User B never sees user A's progress (covered by a test).
- `bun run lint`, `bun run test` and `bun run build` stay green.

### Data flow: client-first answer

```
 user presses Check/Answer
          |
          v
 [pure grader, shared module] --verdict--> UI (instant, <50ms)
          |
          v
 outbox.enqueue({lane, key, idempotencyKey(minted once), owner, body})
          |        \__ localStorage persist (owner-keyed)
          v
 flush loop (ordered per lane) --POST--> route handler
          |                                 | findOne(idempotencyKey) -> early return (replay/2 tabs)
          |                                 | apply + server grade
          v                                 v
   2xx: reconcile (server verdict wins, update item/stage)
   5xx/network: backoff retry (item stays queued)
   4xx: rollback snapshot + visible error
 pagehide: keepalive flush (batches < 64KB); startup: replay leftovers
```

### Failure modes
| New path | Realistic failure | Test | Handling | User sees |
|---|---|---|---|---|
| outbox flush | 5xx or offline mid-session | yes | retry with backoff, stays queued | pending dot, no loss |
| outbox 4xx | expired vocab token | yes | rollback, marked not saved | "not saved" in the summary |
| keepalive on pagehide | body over 64 KB | yes | batching | none (replayed on next load) |
| dictation lane | cursor 409 | yes | re-send with the server cursor | none |
| grammar or vocab reconcile | server verdict differs | yes | server wins | verdict updates |
| segment overlay | attempts query slow | parity | indexed | none |
| unstable_cache | stale catalog after a seed | yes (revalidate route) | updateTag, then the revalidate POST | content refreshes |
| guest mint | two tabs mint at once | yes | `POST /api/guest` returns the existing cookie | none |
No critical gaps: every failure has a test and visible handling.
