## Problem Statement

Grammar v2 shipped 184 rules, a 7-stage review ladder, a test generator, a
comic/creature/sensei layer and a CEFR x difficulty "dungeon" map. The owner
(and only user) opens it and finds it ugly, off-style, demotivating and, in
their words, "khá là vô giá trị". Observed on 2026-10-24 at `/grammar`:

- The copy undermines itself: "Not one of them checked by a human", "every one
  of them a ghost", "This lesson was written by a machine... Be careful".
- There is no way in. A fresh visit shows "NOTHING DUE" and a 6x5 grid of
  "GHOST" cells. Nothing says "do this now".
- Metaphors stack: dojo, bestiary, dungeon, sensei, creature, ghost, scar.
  None of it matches Study Desk or Vocab.
- A lesson is a long wall of English + Vietnamese prose, then nothing to do.

The fix is not a reskin. The owner chose to rebuild everything, content
included, around one loop: a clear course path.

## What Makes This Cool

Open `/grammar`, see exactly one glowing node and a "Tiếp tục" button. Five
minutes later you have stars, a combo sound, an unlocked next node, and the
wrong answers already queued for "Luyện điểm yếu". Over weeks, finished nodes
fade when they are due for review, so the path itself tells you what you are
forgetting. Locked units carry a "Test vượt cấp" chest, so knowing A2 already
costs one 3-minute test, not 25 lessons.

## Decisions From The Session (D1-D8)

- D1 core loop: clear course path (Duolingo-style path, not a dashboard).
- D2 scope: demolish everything, content included.
- D3 lesson shape: learn by doing. 10-15 interactive cards, ~5 minutes, tiny
  teach cards interleaved with practice that applies them. Wrong answers are
  explained on the spot and requeued at the end of the lesson.
- D4 content: Vietnamese explanations, English examples and exercises, about 60
  lessons (12 units x 5) from A1 to C1, weighted toward IELTS and Vietnamese
  learner errors. Quality over quantity.
- D5 motivation: stars + unlocks (+ unit checkpoints and test-out), smart review
  (fading nodes + weak-spot practice), juice (sound, combo, animation).
  Streaks and daily goals were NOT chosen and will not be built.
- D6 premises: all seven accepted (below).
- D7 approach: B, full course engine + full content.
- D8 wireframe: approved (path / practice card / result screen).

## Constraints

- Next.js 16 App Router (read `node_modules/next/dist/docs/` before writing
  route code), React 19, Mongoose, next-auth v5, Tailwind with the manga
  sticker tokens. Rules in `.agents/rules/*.md` apply, notably the sticker
  corner roles, shadcn primitives over raw HTML, and `cn(...)`.
- Two themes exist (light red/white manga and the dark "lamp" theme from the
  pull-string toggle). All new UI uses semantic tokens so both work.
- No em dashes in code, copy or docs (project memory).
- Personal app: one real user plus guests. Server must still own progress
  writes and validate input (api-security rules), but anti-cheat is not a goal.

## Premises (all agreed, D6)

1. The path is the center. `/grammar` shows the A1 -> C1 path with the next node
   lit and a start button. No dashboard, dungeon map, bestiary or test modal.
2. Content is code. ~60 lessons written fresh in Vietnamese, stored as typed
   files in the repo (e.g. `src/modules/grammar/course/units/*.ts`) and
   validated by tests. No DB seeding, no admin, no runtime AI generation, no
   "ghost/unverified" status, no `l1Risk`. Editing a lesson = edit file + commit.
3. The DB stores progress only: per-lesson stars, best accuracy, completion
   date, review stage and due date, plus a log of missed cards for weak-spot
   practice. Old grammar progress is discarded; old collections are dropped by
   a script the owner runs.
4. No streak. Motivation = stars + unlocks + unit checkpoints with test-out,
   fading nodes due for review, "Luyện điểm yếu", and juice.
5. UI matches the rest of the app: sticker blocks with ink borders,
   `MangaButton`/`MangaPanel`, semantic tokens. Remove sensei, creatures,
   comic panels and all self-deprecating copy. Copy is short, positive,
   Vietnamese.
6. Grading is simple and deterministic: each card lists accepted answers;
   normalization covers case, whitespace, curly quotes and trailing
   punctuation only. Contractions are NOT expanded (v2 learning: expanding
   them produced false accepts on perfect tenses). Reuse the shared recall
   ladder (`src/modules/learning/recall/recallLadder.ts`) and the sfx engine
   (`src/lib/audio`).
7. Guests and signed-in users share the same actor pattern as Vocabulary.

## Landscape

Search skipped; the space is well known. Layer 1: Duolingo-style paths with
short lessons, stars and spaced review are the proven pattern for habit-forming
grammar practice. Layer 3: v2's failure was not missing features, it had more
features than any app in the space. It failed on first impression (no next
action, distrustful copy) and on lesson shape (read a wall, then nothing). The
rebuild optimizes the first 10 seconds and the 5-minute loop, and deletes
everything else.

## Approaches Considered

### Approach A: Path MVP

Path + lesson player + stars for the first 3 units (~15 lessons), no review,
no checkpoints. Effort M, risk low. Rejected: drops two of the three
motivation mechanics the owner picked, and the path ends after 15 lessons.

### Approach B: Full course engine + full content (CHOSEN)

All 12 units, five card types, stars, unlocks, checkpoints with test-out,
fading review nodes, weak-spot practice, result screen with juice, Study Desk
tile, complete removal of v2. Effort XL (human ~3-4 weeks / CC ~1 long
session), risk medium (content volume).

### Approach C: Placement-first

B plus an entry placement test. Rejected: per-unit test-out delivers the same
"don't make me redo A1" outcome without a second flow and question bank.

## Recommended Approach

Approach B.

### Lesson anatomy

Each lesson: `id` (stable, e.g. `u06-l04-for-since`), `title` (vi),
`titleEn`, `summary` (one line vi), `cards[]` of 10-15 cards with at least 3
`explain` cards and at least 8 practice cards. Teach cards come right before the
practice cards that use them.

Card kinds:

- `explain`: title, short Vietnamese body (2-4 sentences max), optional
  `formula` (e.g. `S + have/has + V3`), 1-3 examples `{ en, vi }`, optional
  `pitfall` (the typical Vietnamese-speaker mistake, wrong vs right).
- `choice`: prompt, optional sentence, 2-4 options, answer index, explanation.
- `fill`: sentence with one `___`, accepted answers, optional `bank` of tiles
  (tap to fill); without a bank the learner types. Explanation.
- `order`: shuffled word tiles, accepted full sentences. Explanation.
- `fixError`: a sentence as tokens, index of the wrong token, the correction.
  The learner taps the wrong word. Explanation.

Every practice card's explanation is Vietnamese and says WHY in one or two
sentences.

### Player rules

- Progress bar across the top; X to quit (with confirm if mid-lesson).
- Check -> feedback panel (correct: short praise + optional note; wrong: the
  right answer + why). "Tiếp tục" advances.
- A missed card is requeued once at the end of the lesson. Stars use first-try
  accuracy on practice cards only: >= 95% three stars, >= 80% two, otherwise
  one. Finishing always earns at least one star.
- Combo counter on consecutive first-try correct answers; sfx for correct,
  wrong, combo milestones, and lesson complete. Respect the existing sound
  toggle and `prefers-reduced-motion`.
- Keyboard: Enter to check/continue, 1-4 for choice options.

### Path rules

- Lesson N+1 unlocks when lesson N `isPassed` (see State rules). Unit 1
  lesson 1 is always unlocked.
- The checkpoint unlocks when all 5 lessons `isPassed`: 12 questions drawn
  across the unit's practice cards, pass at >= 80%. Passing marks the unit
  complete and unlocks the next unit's first lesson.
- Test-out: any locked unit shows "Test vượt cấp". Passing its checkpoint marks
  every lesson of that unit and all earlier units as passed by test (shown as
  passed, zero stars, replayable for stars) and unlocks the following unit.
- Review: completing a lesson puts it on the shared recall ladder. When due,
  the node renders "faded" with an "Ôn" badge. A review is 6-8 practice cards
  from that lesson; >= 80% advances the stage, below that drops it per ladder
  rules. Path header shows "N bài cần ôn".
- Weak spots: every first-try miss is recorded per card. "Luyện điểm yếu" serves
  up to 12 currently-missed cards (most recent first, across lessons);
  answering one correctly there clears it. Hidden when there are none.

### State rules (precise, from spec review)

- `isPassed(lesson) = stars >= 1 || passedBy === 'test'`. Every unlock rule is
  gated on `isPassed`, never on stars alone.
- Test-out never lowers existing stars or bestAccuracy. Lessons passed by test
  do NOT enter the review ladder (nothing was learned there yet); they enter it
  the first time they are completed as a lesson. A failed test-out changes
  nothing and can be retried at any time.
- Recall: on first completion call the ladder with `isCorrect: true` so the
  first review is due in 1 day (calling the initial-state helper alone would
  make the node due immediately). A review session counts as one ladder answer
  with `isCorrect = accuracy >= 0.8`; a fail drops to stage 1 per the ladder.
  Stage 7 = mastered, the node never fades again. Replaying a finished lesson
  updates stars/bestAccuracy (max) but does not touch the ladder. `dueAt` is an
  absolute UTC instant.
- Sessions: quitting mid-session persists nothing. A requeued card that is
  missed again does not requeue a second time; the lesson still ends.
- Misses: first-try misses in lesson, review and checkpoint modes all upsert
  `GrammarCardMiss` (missCount++, lastMissedAt = now, clearedAt = null).
  A correct answer in weak-spot mode sets clearedAt; a wrong one bumps
  missCount and lastMissedAt and keeps the card open. Test-out misses are NOT
  recorded (the learner has never seen those lessons).
- "Tiếp tục" target order: first unlocked lesson that is not passed, else the
  most overdue review, else weak spots, else a "Đã xong lộ trình" state.
- Review cards: 6-8 practice cards from the lesson, currently-missed cards
  first, rest random. Checkpoint: 12 cards sampled across the unit's 5
  lessons (2-3 each). Test-out uses the same checkpoint builder.
- Server validation: lesson mode requires every practice card of the lesson
  exactly once; review mode 6-8 distinct cards of that lesson; checkpoint and
  test-out exactly 12 distinct practice cards of that unit; weak mode 1-12
  distinct known card ids. Anything else is a 400.
- `fixError`: the learner only taps the wrong token; feedback then shows the
  corrected sentence. No typing.

### Content identity

- Every card has an explicit, permanent `id` (`u06-l04-c07` style). Lesson ids
  and card ids are permanent: the validator enforces uniqueness and format; if
  an id must change, add it to an alias map rather than renaming silently.
- The path service resolves aliases first, then ignores progress and miss rows
  whose ids it still cannot resolve, so removed content never breaks a page or inflates counts.

### Guest to user

- Add a grammar step to the existing guest merge (`mergeGuestData.ts`, today
  dictation-only): lesson progress takes max stars and bestAccuracy, earliest
  completedAt, and keeps whichever side has a ladder row (the user's if both
  do); unit progress
  keeps the earliest pass; misses are unioned (max missCount, latest
  lastMissedAt). Done with per-row upserts to avoid unique-index collisions.

### Content quality

The "unverified" banner is gone, so quality must be earned rather than
disclaimed. Each unit is written, then checked by the validator AND an
independent reviewer pass (a fresh agent reading the unit for grammar errors,
wrong answers, ambiguous items with more than one valid answer, and unnatural
Vietnamese) before it lands. Build order: engine + unit 1 end to end first, then
the remaining units in parallel batches.

### Screens

- `/grammar`: header strip (total stars / max, current unit, due-review count),
  primary CTA "Tiếp tục: <next lesson>" and secondary "Luyện điểm yếu (n)",
  then the vertical path grouped by unit banners. Current node is larger and
  lit; done nodes show stars; due nodes are faded; locked nodes are dashed.
- `/grammar/lessons/[lessonId]`: the player (full-screen focus layout).
- `/grammar/units/[unitId]/checkpoint`: player in checkpoint mode.
- `/grammar/review/[lessonId]` and `/grammar/practice`: player in review and
  weak-spot modes.
- Result screen inside the player: stars animate in, accuracy, best combo,
  time, "Đã thêm n câu vào Luyện điểm yếu", "Mở khóa: <next>", buttons
  "Bài tiếp theo" / "Làm lại để lấy 3 sao".
- Study Desk: the Grammar module tile/row shows the next lesson and due count.

### Data (progress only)

- `GrammarLessonProgress`: actor id, lessonId, stars (0-3), bestAccuracy,
  passedBy ('lesson' | 'test'), completedAt, recall stage, dueAt, attempts.
  Unique (actor, lessonId).
- `GrammarUnitProgress`: actor id, unitId, checkpointPassedAt, passedBy.
- `GrammarCardMiss`: actor id, cardId, lessonId, missCount, lastMissedAt,
  clearedAt. Unique (actor, cardId).
- One write endpoint per finished session: `POST /api/grammar/sessions` with
  `{ mode, lessonId | unitId, results: [{ cardId, firstTryCorrect }],
idempotencyKey }`. The server validates every cardId against the static
  course, recomputes stars/pass from the results, applies unlock/review/miss
  updates, and returns the new path state. Follow the repo idempotency
  convention (unique (actor, idempotencyKey)).
- Reads happen in server components via a `getGrammarPathForActor` service.

## Success Criteria

- A fresh guest lands on `/grammar` and starts lesson 1 in one click.
- All 60 lessons and 12 checkpoints exist, pass the content validator (card
  counts, every fill/order answer reachable from its tiles, choice answer index
  in range, no em dashes, Vietnamese explanation present on every practice
  card), and render in both themes on phone and desktop.
- Finishing a lesson awards stars, unlocks the next node, records misses, and
  schedules review, verified by service tests and a browser run.
- Test-out on unit 4 marks units 1-4 passed and opens unit 5.
- No file, route, asset, or token from v2 remains (grep for `sensei`,
  `creature`, `dungeon`, `bestiary`, `l1Risk` returns nothing outside the
  drop script).
- `bun run lint`, `bun run test`, and `bun run build` pass.

Findings folded in:

  idempotencyKey); one automatic retry after 1.5s, then "Chưa lưu được. Thử lại".
  Leaving the result screen while unsaved asks for confirmation. Retries reuse
  the same idempotencyKey. A 400 for unknown card ids shows "Bài vừa được cập
  nhật" and returns to the path.
- 4.1 Leave guard: X asks "Bỏ bài? Tiến độ bài này sẽ mất" once at least one
  card is answered; `beforeunload` guard in the same condition. Typed-answer

- 4.2 Permanent redirects in next.config: `/grammar/points/:path*`,
  `/grammar/archive`, `/admin/grammar/:path*` -> `/grammar` (admin -> `/admin`).
- 5.1 One pure `buildGrammarPath(courseIndex, lessonProgress, unitProgress,
misses, now)` returns the whole path view model (node states, CTA target,
  due count, weak count). Table-driven tests. No multi-file presentation layer.
- 6.1 All randomness (order-tile shuffle, review pick, checkpoint sample, choice
  shuffle) takes an injected seedable `rng`.
- 8.1 Structured server log on session reject/failure: actor kind (guest/user),
  mode, lessonId/unitId, reason. No PII beyond the existing actor id.
- 11.1 Mobile/a11y: sticky bottom action bar in the player; path fits 375px;
  feedback in an `aria-live="polite"` region with icon + text (never color
  only); tiles and options are real buttons with visible focus; 1-4 / Enter
  shortcuts on desktop.
- Deploy: ship v3, verify, only then run `dropLegacyGrammar`. Before the drop,
  rollback = git revert with v2 data intact; after the drop, v2 is gone.

## Eng Review Amendments (2026-10-24, FULL_REVIEW)

- A1 Server owns correctness: the client posts `{ cardId, firstAnswer }` per
  card (the raw first answer: option index, typed/bank text, ordered tiles,
  tapped token index). The server re-grades with the same pure `gradeCard`
  the client uses for instant feedback. The client never sends verdicts.

  only applies them (pattern: `itemStatusPatch.ts`). Guest merge uses a pure

  (read-only) in server pages; no id yet = empty progress, lesson 1 open.
- Checkpoint/test-out accept any 12 distinct practice cards of the unit (the
  page samples them with a seeded rng); no server-issued exam token.
- Tests: table tests for gradeCard, scoring, buildGrammarPath,
  planGrammarSessionWrite, planGrammarGuestMerge, rng; the course validator runs
  over all content; player component tests (requeue, combo, leave guard, save

Everything in this doc and both review amendments shipped. Where the code

- **Save failure (CEO 2.1).** A finished session goes through the shared
  client outbox (`src/lib/sync/clientOutbox.ts`) in the `grammar` lane, built
  by `buildGrammarSessionWrite` in `src/requests/grammarSessionsApi.ts`. The
  outbox stores it before sending, retries with the same idempotency key,
  replays it on the next load, and tags it with the hashed owner key, so a
  shared browser never replays one learner's lesson as another's (the route
  answers 409 on a mismatch). The result screen says "Đang chờ mạng" after
  6 seconds; the path page shows a saving hint and refreshes once the lane
  drains. The raw guest id is never rendered to the client.
- **Indexes.** Production connects with `autoIndex` off, so the four grammar
  models are listed in `scripts/syncIndexes.ts`; run `bun run db:sync-indexes
  --apply` after deploying. The unique `(userId, idempotencyKey)` index on
  `GrammarSession` is what makes the claim-first dedupe safe.
- **Idempotency is claim-first.** `recordGrammarSession` inserts the
  `GrammarSession` record (response `null`) before reading or writing; a
  concurrent duplicate gets a retryable 503 and later replays the stored
  result. A failed write releases the claim; an abandoned claim expires after
  60 seconds.
- **Weak-spot sessions** accept only cards with an open miss row.
- **Order cards** show the sentence's end mark (`.` or `?`) as a fixed glyph,
  so a statement card cannot be answered with a question word order.
- **Sound** turned on in one lesson keeps playing in the next: `play()` mints
  the AudioContext inside the first sting's gesture.
- **Guest merge failure** keeps the guest cookie, so the next sign-in retries.
